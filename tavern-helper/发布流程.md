# 电波手机发布流程

当前发布版本：`1.1.32`

## 版本规则

- 发布版本写在 `电波手机/schemas.ts` 的 `WAVE_PHONE_RELEASE_VERSION` 中。
- 构建文件使用 `file/index-版本号.js`，例如 `file/index-1.0.1.js`。
- 已发布的文件不要覆盖。每次更新都递增版本号并创建新文件，避免酒馆和 CDN 继续使用旧缓存。
- `WAVE_PHONE_STORAGE_VERSION` 是数据结构版本，普通功能更新不要修改；只有存储格式发生不兼容变化时才递增并提供迁移逻辑。

## 1. 修改版本号

例如从 `1.0.0` 更新到 `1.0.1`：

```ts
export const WAVE_PHONE_RELEASE_VERSION = '1.0.1';
```

## 2. 检查并构建

在 Tavern Helper Template 项目根目录执行：

```powershell
pnpm install
pnpm exec eslint "src/util/酒馆助手脚本/电波手机"
pnpm build
```

生产构建位于：

```text
dist/util/酒馆助手脚本/电波手机/index.js
```

不要使用 `pnpm build:dev` 的产物公开发布；开发构建体积更大，也包含不必要的调试内容。

## 3. 复制并改为版本文件名

把生产构建复制进本仓库，文件名必须使用本次的新版本号：

```powershell
Copy-Item `
  "dist/util/酒馆助手脚本/电波手机/index.js" `
  "Electric-Phone/file/index-1.0.1.js"
```

同时把最新的 `电波手机` 源码目录同步到本仓库的 `tavern-helper/电波手机/`。

## 4. 提交、打标签并推送

在 `Electric-Phone` 仓库内执行：

```powershell
git add README.md file tavern-helper
git commit -m "release: electric phone v1.0.1"
git tag -a v1.0.1 -m "Electric Phone v1.0.1"
git push origin main
git push origin v1.0.1
```

标签和文件名必须与 `WAVE_PHONE_RELEASE_VERSION` 一致。

## 5. 在酒馆助手中更新导入地址

推荐使用版本标签链接，内容固定、便于回滚：

```js
import 'https://cdn.jsdelivr.net/gh/colerith/Electric-Phone@v1.0.1/file/index-1.0.1.js';
```

也可以跟随 `main`，但仍要修改文件名来绕开旧缓存：

```js
import 'https://cdn.jsdelivr.net/gh/colerith/Electric-Phone@main/file/index-1.0.1.js';
```

保存酒馆脚本后，停用再启用一次脚本或刷新页面。若旧版仍在运行，确认导入地址中的标签和文件名都已换成新版本。

## 6. 发布校验

先在浏览器访问对应 jsDelivr 地址，确认返回 JavaScript 而不是 404。再在酒馆开发者工具中检查是否有加载错误，并到电波手机的设置页核对显示的版本号。

如需紧急回滚，只需把酒馆脚本中的导入地址改回上一个版本标签和文件名；不要删除已发布的旧构建。
