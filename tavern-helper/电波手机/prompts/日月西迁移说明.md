# 提示词条目与酒馆同步

`prompts/index.ts` 的 `BUILTIN_PRESET_ENTRIES` 统一容纳创作条目、生成总则、私聊规则、各 App 规则、路由、动态上下文和最终输出协议。原本分散的 GENERATION_RULES、BASE_PROMPT、CHAT_PROMPT、APP_PROMPTS 等内容已收进数组，不另行重复拼接。

条目分为 custom（静态规则）、builtin（酒馆原生占位条目）和 runtime（电波手机当前数据）。scope 区分私聊与空间，生成最终格式不会互相覆盖。

| 原生条目 | 同步来源 |
| --- | --- |
| char_description / char_personality / scenario | 酒馆当前角色描述、性格、场景 |
| persona_description | 酒馆当前用户人设 |
| dialogue_examples | 当前角色对话示例 |
| world_info_before / world_info_after | 酒馆本轮世界书触发结果，遵循绑定、启用、关键词及位置规则 |
| chat_history | 酒馆当前正文历史，保留原生作者注释与深度世界书处理 |
| user_input | 本轮实际手机输入，含时间与设备感知 |

旧 marker 已替换，不复制整本世界书，也不持久缓存角色/用户资料。通过 generateRaw 的 ordered_prompts 传入原生键，每轮由酒馆本体展开。主 API 与追加模式本来就经过酒馆生成管线，仅额外补入手机规则与手机数据。

手机自己的私聊记录、目标身份、App 快照、日程与空间互动在原条目位置动态填充，按当前 Char 隔离。发送前、重试前和返回后核对聊天命名空间；切换聊天会取消旧请求结果。

预算说明：本地裁剪只计算显式手机规则、私聊记录与本轮输入；原生角色、人设、世界书和正文在酒馆内部展开，最终长度受酒馆与模型上下文限制，不能把本地估算当作完整 token 总数。
