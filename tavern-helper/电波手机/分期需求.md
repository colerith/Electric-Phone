# 电波手机：本轮分期需求与提示词计划

本文件对应 2026-09-14 的“我的、钱包、聊天清理、生成设置和 NPC 社交”需求。状态分为已实现、待实现；待实现能力不提前注入实际模型请求。

## 第一批：本次完成

- [x] 朋友圈提示词集中到 `prompts/index.ts`：静态规则、身份约束、请求数据组装和最终输出协议。`prompts/moments.ts` 仅兼容旧导入。
- [x] “我的”首页去掉右上编辑按钮；编辑资料、我的朋友圈、朋友圈互动进入独立子页层级。子页无 Dock、无内容区额外返回键，标题由顶部导航显示，顶部返回逐层返回；我的朋友圈右上可发布。
- [x] 浏览历史和收藏夹支持删除单条，当前角色独立保存；删除历史不同时取消收藏，删除收藏不同时删历史。

## 第二批：聊天对象与清理（已实现）

- [x] 私聊设置增加对象类型：主要角色 / NPC。
- [x] 与 User 的关系支持自定义及恋人、朋友、闺蜜、亲人等参考项。对象类型、关系和联系人备注独立保存，切换角色不会串用。
- [x] 已有联系人设为 NPC 后可编辑人设，按稳定联系人 ID 保存，在私聊与朋友圈请求中复用。头像沿用现有私聊修改入口；场景生成 NPC 的持久身份与加好友入口仍属于第五批。
- [x] 设置最底部增加“清空聊天记录”“清空聊天记录与历史上下文”两个按钮；点击后在手机内说明清理范围并确认。清空需处理当前生成取消、缓存与来源重放，避免下次同步复活。
- [x] 第一项清除手机可见聊天；第二项同时清除该对象后续请求会引用的手机历史、摘要和上下文索引。酒馆正文与其他联系人不直接删除；需设计上下文截止点，使被清空部分不被再次注入。
- 提示词落点：`电波手机·身份与信息边界`、`电波手机·私聊回复`、`电波手机·私聊记录`；结构化输入明确 `{actorId, actorType, relationshipToUser, profile, historyCutoff}`。按 ID 区分 User/主要角色/NPC，只使用允许的历史窗口，不自行恢复已清理记录，不把人设文本作为系统指令。

- 实现记录：普通清理将已发送记录移入隐藏历史；彻底清理清除此历史、当前记录及手机请求的旧正文窗口。楼层截止点阻止旧手机数据重新展示；生成修订号和取消标记拒绝迟到结果。其他应用、角色资料和酒馆原文保留。
- 边界：主 API/追加模式的正文历史仍由酒馆管理，手机脚本只移除自己的手机参考，不删除或全局隐藏酒馆楼层。独立 API 使用该联系人专属楼层截止点。
- 验证：模拟清理确认/取消、普通清理后保留参考、彻底清理后不再注入、来源回放、后续新楼层、迟到回复、联系人资料保存和其他数据保留；真实酒馆联调仍待执行。

## 第三批：生成数量与双语（已实现）

- [x] 备忘设置：双语配置复用私聊语言选择和展示方式；每轮新增便签、涂鸦各自滑块，允许 0–5。
- [x] 空间设置：双语配置及每轮新增动态上限滑块，0–5。
- [x] 日历设置：每轮新增日程上限滑块，0–5；不添加双语要求。
- [x] 浏览设置：双语配置及每轮新增浏览手记上限滑块，0–5。
- [x] 手动生成、独立 API、跟随正文使用同一配置快照；提示词和解析校验同时限量。上限是新增数量，旧项更新不重复计数，没有合理内容可少于上限；0 表示禁止新增。
- 提示词落点：各 `电波手机·应用规则·memo/zone/calendar/browse` 条目，明确新增上限与原 ID 更新；双语使用可校验的原文/译文结构，不混入标题或伪造翻译。旧纯文本数据兼容显示，单语模式不强制译文。涂鸦数量需与实际备忘存储结构一起升级。

- 实现记录：各应用设置新增独立卡片，便签/涂鸦分开计数；默认上限 3，可调 0–5，立即保存。备忘、空间与浏览复用私聊语言选项，分别设置输出语言、译文语言、自动附带与自动展开。
- 数据协议：备忘使用 notes/doodles 数组，日历使用 events，浏览使用 notes；每项具有稳定 id，旧纯文本兼容解析。备忘可展示多张涂鸦，保留 ASCII 空格与换行；translation 使用独立 language/title/content，涂鸦仅翻译文字解析。
- 执行边界：手动模块、空间独立更新、私聊附带更新、跟随正文都进行结果限量。同一角色同一楼层的多个数据块共享新增额度；跟随完成后裁剪数据再生成文中卡片，关闭文中卡片也执行限量。请求开始固定配置，楼层保存本轮配置用于重放；中途修改设置不影响当前请求。
- 旧版迁移：已同步历史楼层保留原有内容，不以新上限截断旧记录；新请求向模型提供旧条目的稳定 ID。旧记录不强行补译，缺少译文时保留原文，不伪造译文；已有译文可折叠阅读。
- 验证：实际 Vue 组件与 Pinia 测试覆盖滑块保存、各应用独立设置、日历无双语项、多涂鸦、译文展开/收起；覆盖所有 0–5 边界、旧 ID 更新、重复 ID、跨块额度、手动与跟随配置快照、私聊附带与独立空间结果、楼层重放和旧版历史保留。真实酒馆与模型联调待执行。

## 第四批：我的钱包与共享账户（已实现）

- [x] “我的”增加“我的钱包”独立子页，可设置金额、币种和银行卡等账户资料。
- [x] 钱包设置增加货币选项与共享账户选择；我的钱包与钱包 App 使用同一账户数据源。
- [x] 支持记录自己的收入与支出；钱包 App 中明确区分 User 账本与 Char 账本，共享账户作为独立归属呈现，避免两处重复入账。
- [x] 模型只能更新本次授权的剧情账户，User 手工金额和银行卡资料不得被自动生成覆盖。币种切换不擅自按 1:1 换算；跨币种流水需保留原币种或明确汇率输入。
- 提示词落点：`电波手机·应用规则·wallet`；输入输出绑定 `{accountId, ownerType:user|char|shared, ownerId, currency}`，稳定交易 ID、金额、收入/支出方向及 pending/received/refunded 状态；不得猜银行卡号码或声称真实支付。User 与 Char 的余额分开结算，共享账户更新只提交一次。

- 实现记录：“我的钱包”是独立子页，隐藏消息 Dock，使用顶部返回；可编辑账户名称、币种、当前余额、银行名称、卡片备注和卡号后四位，；收支、账单和统计仅在钱包 App 提供。钱包 App 用“我的 / 角色 / 共享”标记区分账户。
- 共享机制：同一聊天内的两个入口共用 `walletBook`。可创建多个共享账户，按当前联系人选择一个用于剧情记账；我的私人钱包不进入模型可写范围。每个聊天独立保存账户，不跨角色卡共享资金。
- 余额与币种：按币种分别保存余额基础与流水，切换币种显示对应账本，不换汇，不重写旧流水。修改银行资料不会将余额回退到表单旧值。未知余额继续显示“—”，可手工设置。
- 生成与保护：`prompts/index.ts` 集中维护钱包规则及本轮授权，手动/私聊附带/跟随生成携带 accountId、ownerType、ownerId、currency。验证端拒绝错误归属和币种；银行卡不放入请求。手工流水优先，模型不能覆盖用户输入的总余额或银行卡。
- 幂等与重放：同账户按交易 ID 去重，pending/received/refunded 更新同一记录并重新计算余额。楼层保存账户授权，后续改选共享账户不重定向旧流水；删除或改写楼层重建对应模型记录，手工记录保留。旧版手工账目和余额兼容迁移。
- 验证：实际 Vue 表单、账户选择、币种切换、我的钱包导航；Pinia 保存/重放；共享不重复扣款、退款、账户越权、银行卡保护、生成中切换账户和旧版迁移均有测试。构建和电波手机模块类型检查通过；真实酒馆与模型联调待执行。

## 第五批：朋友圈 NPC 身份页与加好友（已实现）

- [x] 场景 NPC 生成用户名和稳定人物 ID，点击作者姓名或头像进入微信风格介绍页，展示用户名、头像、简介及关系。
- [x] 介绍页支持添加好友；加入联系人按稳定 ID 去重，保留此前朋友圈身份与人设，之后可发起私聊。
- [x] 使用免费公共头像服务生成默认插画头像，具体服务、免费使用条件及风格需实施时核查；使用 NPC 稳定 ID 作为随机种子，用户自定义头像优先。
- [x] 同一 NPC 跨轮保持用户名、头像及人设一致。现有按请求创建的临时 NPC 需迁移为持久身份，不能把相同昵称直接当作同一人。
- 提示词落点：`电波手机·朋友圈互动`，必要时增加对应身份子条目。请求携带已知人物表，新增 NPC 返回 `{npcId, username, profile, avatarSeed}`；authorKey 必须绑定人物表，不能冒充 User、Char，不编造远程头像 URL，由脚本生成资源地址。添加好友不改变人物身份，只改变联系人状态。

- 实现记录：朋友圈新增持久 NPC 人物表，计划中复用旧 NPC，同时允许按场景规则创建新人物。新增资料只接受本轮预留 ID，用户名与人设固定保存；同名人物不按名字合并，添加通讯录后保留原 NPC ID。
- 资料页：帖子头像、作者、评论者和点赞者均可打开 NPC 介绍页，显示昵称、电波账号、人设和关系；子页隐藏 Dock，不沿用朋友圈壁纸，仅使用顶部返回。添加到通讯录后可发消息，私聊设置继续编辑关系、人设及头像。
- 提示词：`prompts/index.ts` 集中维护 knownNpcs、isNew、npcId/username/profile/avatarSeed 协议；校验端拒绝未授权人物、冒充 User、任意头像种子与擅自更改旧人物资料。用户编辑的人设在后续私聊和朋友圈共同使用。
- 头像：使用 DiceBear 10.x Notionists 公共 SVG API，稳定种子由脚本基于 NPC ID 生成，不向头像服务提交姓名或人设。自定义头像优先，恢复默认回到原种子；加载失败显示昵称首字。已验证接口返回 200 / image/svg+xml。
- 来源：[Notionists（Zoish，CC0）](https://www.dicebear.com/styles/notionists/)、[HTTP API（免认证）](https://www.dicebear.com/integrations/http-api/)。服务可用性依赖网络，界面有失败回退。
- 迁移与验证：兼容旧 ambient NPC 的 ID 和昵称，缺失人设保持空白、不杜撰。实际 Vue / Pinia 测试覆盖资料导航、添加好友去重、同名不同 ID、已有 NPC 复用、头像失败/自定义/恢复、人设长文本保存、旧事件重放和越权输出拒绝。真实酒馆视觉及模型联调待执行。
