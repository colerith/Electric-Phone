# 电波手机脚本组件规范

## 1. 设计来源与迁移边界

本规范提炼自 `D:/SillyTavern/电波系出品/电波机/app`
的设计令牌、卡片层级、自定义选择器、复选交互和图片上传流程。电波手机只迁移视觉语言与交互原则，不引入原项目的 React、Next.js、Radix
UI 或服务端依赖；所有组件均改写为可由酒馆助手脚本打包的 Vue 组件。

核心设计令牌：

- 深蓝：`#204075`
- 电波蓝：`#5e80be`
- 电波粉：`#fc9fbb`
- 正文：`#374558`
- 次要文字：`#6e7682`
- 中文界面字体：`PingFang SC`、`Microsoft YaHei`；展示性标题允许使用宋体/衬线字体。
- 主页可保留低对比蓝粉渐变；所有子页面使用中性灰白（深色模式使用中性黑灰），操作卡片使用实色白底、克制阴影和等半径圆角。详见 1.2
  SwiftUI 风格统一规范。

### 1.1 原电波机视觉规范快照（消息颜色语义；圆角与表面服从 1.2）

本节根据原项目 `D:/SillyTavern/电波系出品/电波机/app/app/globals.css`、
`components/ui/checkbox-list.tsx`、`components/ui/bulk-action-bar.tsx`
和用户确认的消息参考图补全。后续修改消息 UI 时，必须先按本节判断组件属于“气泡”还是“结构化卡片”，不能把发送者颜色机械铺满所有消息。

| 令牌     | 固定值    | 正确用途                                                |
| -------- | --------- | ------------------------------------------------------- |
| 深蓝     | `#204075` | 主按钮、重点标题；不作为 User 消息或大面积转账底色      |
| 电波蓝   | `#5E80BE` | Char 强调色、图标、定位点、选中状态                     |
| 电波粉   | `#FC9FBB` | User 强调色、图标和少量装饰；禁止直接作为大面积卡片底色 |
| 正文     | `#374558` | Char/User 共用的主要文字，不能为了区分发送者改成紫红色  |
| 次要文字 | `#6E7682` | 时间、说明、次级状态                                    |
| 中性表面 | `#F2F1F3` | 媒体占位、功能区和多选高亮                              |
| 白色表面 | `#FFFFFF` | 位置、链接、通话等结构化信息卡                          |

消息配色与结构规则：

- 普通文字气泡：Char 使用低饱和淡蓝 `#DCE8F8`，左上小直角；User 使用电波粉低透明度混白得到的淡粉
  `#FEDCE7`，右上小直角（见 1.3 最新消息参考）。两侧文字统一 `#374558`，只允许极轻的中性阴影。
- 语音属于气泡型消息，可沿用同侧淡蓝/淡粉底；播放圆钮与波形分别使用 `#5E80BE` /
  `#FC9FBB`。播放钮、波形、时长必须是三个稳定对齐区，不允许继承通用按钮宽高后互相覆盖。
- 图片与视频属于媒体卡：真实媒体保留原图颜色；无媒体时统一使用 `#F2F1F3`
  中性占位，只有图片图标或视频播放钮使用发送者强调色。禁止把整个媒体卡染成蓝色或粉色。
- 位置、链接与通话属于结构化卡片：卡片固定为白色或近白实色，边框和阴影保持中性；仅定位点、类型图标或小标签跟随发送者蓝/粉强调色。
- 转账属于纪念票据：参考原电波机轻纸张质感，使用近白雾蓝/雾粉的低对比背景、蓝色金额、粉色手写体装饰、细分隔线和小状态章。禁止使用高饱和深粉或深蓝整卡填充。
- 撤回与系统提示固定使用中性浅灰，不跟随发送者染色。
- 发送者差异应通过气泡方向、对齐和局部强调色表达；不得定义一个通用 `sender background` 并套用到所有消息种类。
- 阴影统一从 `rgba(55, 69, 88, 0.06–0.10)` 取值；避免粉色阴影、蓝色阴影或高饱和发光。
- 图标容器必须使用明确的 `width/height` 或 `aspect-ratio: 1` 并以 `display: grid; place-items: center` 居中；Font
  Awesome 播放三角可向右光学校正 1–2px。

### 1.2 SwiftUI 风格统一规范（2026-09-12）

按用户最新参考图，电波手机采用 SwiftUI 启发的分组界面语言，以 Vue/CSS 实现，不引入 Swift 运行时。此节取代旧规范中的彩色页面底、非对称圆角和厚重装饰。

- **统一表面**：主页可保留原渐变。七个应用、设置与其他子页面使用 `--wave-surface: #F2F2F2`，卡片
  `--wave-card: #FFFFFF`，内嵌控件
  `--wave-tint: #F3F3F3`；顶部系统栏和导航栏与页面同色。禁止蓝底、粉底、深蓝余额卡和按应用切换背景主题。
- **深色模式**：对应使用 `#1C1C1E`、`#2C2C2E`、`#363638`，保持中性色；不使用蓝紫底。原始照片与媒体本身的颜色不受限制。
- **颜色的职责**：电波蓝用于少量数值、图标与选中态；柔和粉色只用于极细指标或少量交互强调。禁止用强调色铺满内容卡片、封面或大面积装饰。
- **形状与层级**：分组卡片统一 22px 等半径圆角，内嵌标签 12px；圆形图标按钮保持 1:1。禁止异形矩形、切角和多层套框；普通消息气泡按 1.3 的最新参考保留一侧小直角。分组主要靠留白与中性细分隔线组织。
- **间距**：页面横向 18px，卡片内边距 18px，组间 14–16px，双列间距 12px；窄屏可降为 12px 内边距与 8px 列间距。
- **字体层级**：UI 与正文使用统一字体令牌；角色名可沿用电波展示字体，数字使用无衬线等宽数字。中文信息为主，英文分类仅用 8–9px 的灰色辅助标记，不做大字海报。页面标题只在导航栏出现一次。
- **阴影**：中性轻阴影 `0 2px 5px rgba(0,0,0,.025)`，边线 `rgba(35,35,38,.08)`；禁止彩色光晕、强投影和拟物高光堆叠。
- **交互**：只有可操作内容才有按钮外观；情绪标签为静态文本，不伪装开关。按压与数值变化使用 160–280ms 的轻反馈，尊重减少动态效果偏好；缺少数据显示“—”与说明，不伪造 0%、在线状态或变化量。
- **布局**：长文本自然折行、纵向滚动；隐藏系统滚动条但保持滚动能力。子组件不能撑出手机边界，不能覆盖状态栏。
- **复用**：七个应用共享 `styles/apps/apps.scss` 的表面与卡片令牌，状态专属样式以 `status-` 命名，不改变消息气泡的独立颜色语义。

### 状态面板组件结构

`WaveStatusPanel.vue` 作为状态页挂载组件，信息类型与 ta 的手机原生面板对应，视觉遵循上述统一规则：

1. 角色档案：辅助标签、角色名、头像与真实的数据可用状态；不重复“状态”页面标题。
2. VITALS / DESIRE：两列指标，百分比、细进度条、独立变化说明；正确保留小数、负变化和括号说明。
3. MOOD：独立情绪分组，标签自动换行。
4. ANALYSIS：完整隐秘心声，保留换行，使用轻引用标识和舒适行距。
5. ORGANS：一个分组内的器官名称与描述列表；兼容 `【器官名】描述`、`器官名：描述` 及多行续写。

空数据仍显示同类型组件的空态；不隐藏整页、不随机补值。状态解析保持纯函数，显示内容使用 Vue 文本插值，不执行角色输出中的 HTML。

### 1.3 消息与备忘细节（最新参考修订）

- 普通文字气泡以最新蓝粉参考为准：Char `2px 21px 21px 21px`，User
  `21px 2px 21px 21px`，无描边、无明显阴影；这是通用等半径圆角的唯一消息形状例外，不推广到按钮和容器。
- 对方头像在左、User 头像在右，与消息首行顶部对齐。头像固定 30px 正圆，与内容间距 8px，双方均显示当前资料头像；User 跟随酒馆当前 persona 变化。多选控件必须预留宽度。
- 视频卡按参考图使用深墨色媒体背景（不作为页面背景），播放按钮为半透明灰白圆钮与白色三角。按钮/视频区、描述和错误反馈分开排布；描述自然撑高，不与播放键重叠，不重复展示。暂停后保留原生媒体控制能力。
- 照片使用拍立得白纸边框、正方形照片区域与底部说明留白；缺少资源时保留中性照片占位。图片与描述不能绝对定位叠压。
- 备忘采用独立 `WaveMemoPanel`，保留 ta 手机的标题分组、列表、多行正文、ASCII 涂鸦与多行解析。
- 备忘页面底保持中性灰白；纸张便签、局部低饱和胶带、回形针、票据虚线与条码作为内容装饰，不能把整个模块染色。图案只用于细小装饰，不使用大面积彩色渐变。
- 便签支持展开/折起、全文搜索、全部/便签/涂鸦筛选；涂鸦使用等宽字体，保留空格和换行，超宽内容在自身区域横向滚动。装饰不伪装可操作按钮，不虚构日期、事件或笔记数据。

## 2. 强制禁用项

业务模板中禁止出现以下可见组件：

- `<h1>`–`<h6>`。标题统一使用带明确类名的 `div`、`span` 或 `strong`，避免酒馆主题的标题字号与边距覆盖。
- 原生 `<select>`。统一使用 `WaveSelect` 的按钮触发器与 `role="listbox"` 弹层。
- 原生 `radio` 与 `checkbox`。单开关使用 `WaveToggle`；多项选择使用自定义按钮并标注 `aria-pressed` 或等价 ARIA 状态。
- 可见的原生文件上传框。文件选择器只允许作为视觉隐藏的能力入口，用户必须通过 `WaveImageUpload` 的自定义预览和弹窗操作。
- 浏览器默认弹窗和未经设计的默认控件皮肤。
- 可见滚动条。需要滚动的区域继续支持触控、鼠标滚轮与键盘滚动，但必须同时隐藏 WebKit、Firefox 与旧版 Edge 的滚动条。

文本框、数字框和文本域可以使用原生输入能力，但必须应用电波手机自己的边框、背景、焦点环、字体和数字箭头处理。

## 3. 主题隔离

- 所有运行样式必须位于唯一根节点 `#wave-phone-script-root` 下。
- 样式文件中的旧式组件规则也必须整体嵌套在根节点内；禁止将 `.conversation-row`、`.composer`、 `.settings-card`
  等通用类名直接传送到酒馆页面。
- 根节点使用 `all: initial`、`color-scheme: only light` 和 `contain: style` 建立样式边界。
- 按钮、输入框和文本域显式重置 `appearance`、字体、阴影、字距、大小写与透明度。
- 组件选择器以根节点 ID 开头，提高优先级，避免 SillyTavern 美化主题重写控件。
- 弹层的层级必须高于手机壳；事件监听使用组件实际元素的 `ownerDocument`，不能假定脚本 iframe 的 `document` 就是挂载页面。
- 不使用 Shadow DOM，以保持酒馆助手的样式传送与 Font Awesome 图标兼容。
- 控件重置不得设置会覆盖组件布局的通用宽度；按钮宽度必须由具体组件决定。

## 4. 基础组件

### WaveSelect

- 触发器是 `button`，带 `aria-haspopup="listbox"` 与 `aria-expanded`。
- 选项是按钮式 `role="option"`，通过 `aria-selected` 表示选中状态。
- 支持点击外部和 Escape 关闭；上、下方向键可改变当前值。
- 选项允许一行说明，避免只靠缩写表达副 API 等复杂设置。

### WaveToggle

- 使用 `button role="switch"`，通过 `aria-checked` 暴露状态。
- 轨道、滑块、开关色和动画全部由脚本样式绘制，不调用浏览器 checkbox 皮肤。
- 关闭轨道为中性浅灰，开启轨道为电波蓝实色，滑块恒为白色；开关中禁用蓝粉渐变。

### WaveSlider

- 原生 range 仅作为透明的键盘、触控输入层，用户看到的轨道、进度、圆形滑块和阴影全部由 `WaveSlider` 绘制。
- 组件样式必须带 `#wave-phone-script-root` 前缀，不允许酒馆主题改写滑轨或滑块。
- 未完成轨道使用浅灰实色，已完成轨道使用电波蓝实色；滑块使用蓝芯、白色描边和轻阴影，不使用多色渐变。

### WaveImageUpload

- 点击头像预览打开自定义编辑弹窗。
- 支持酒馆 `/characters/...` 等内部头像路径、本地图片与公开 `http/https` 图片地址。
- 本地文件限制为图片且不超过 12MB；使用 Canvas 将最大边压到 1200px，并以 JPEG 0.82 质量保存为数据地址。
- 提供预览、错误提示、确认和“恢复卡片头像”。
- 提供可拖动的头像选区、100%–250% 缩放、水平/垂直偏移和一键居中；24px、40px、58px三档小头像必须同步预览最终效果。
- 缩放与选区参数和头像地址一同持久化，并应用到首页身份条、Char 卡片、会话列表和聊天气泡头像。
- 水平和垂直选区必须使用可见的图层平移，不能只依赖正方形图片上无视觉差异的 `object-position`。
- 编辑卡片、预览区、参数区和上传区使用不透明实色表面，避免内容与顶部栏透出。
- 头像修改器必须作为手机导航栈中的正式子页面展示，不再使用覆盖状态栏的模态弹窗；返回按钮回到 Char 信息页。
- 选区偏移上限必须随缩放量动态计算，任何缩放与位移组合都不能让头像容器漏出底色。
- 隐藏的 `<input type="file">` 仅用于唤起系统文件选择，不作为界面组件展示。

### 顶部系统区

- 时间固定显示在状态栏左侧，不进入灵动岛；灵动岛只保留无文本的听筒/镜头装饰。
- 二级页面的状态栏与应用导航栏使用同一背景，不能出现上下分段或状态栏未跟随的情况。
- 头像外围的轨道装饰必须保持 `1:1` 正圆，不允许因容器尺寸形成椭圆。
- 设置入口放入主屏应用网格，并复用普通应用卡片的尺寸、排版、图标容器、圆角与阴影。
- 设置采用“首页分类 → 分类详情”的二级结构，固定保留 API 设置、聊天与行为、语音与媒体、通知与音效。
- 设置额外提供“字体与显示”模块，可选系统字体、思源宋体和思源黑体，并能调整 UI 整体字号与 400–900 的展示字重。

### 弹层与聊天底部区域

- 头像编辑遮罩限制在手机设备边界内，弹窗自身不得超出手机；遮罩必须覆盖并弱化顶部系统区。
- 私聊列表项必须填满内容区域，不得因基础按钮重置退化为内容宽度。
- 输入栏、扩展栏和底部 Home 条使用连续背景，不得出现颜色断层。
- 消息二级面板使用白色/雾蓝实色卡片、深色正文和深蓝实色主按钮；右上角关闭按钮固定为 1:1 正圆。
- 所有“保存”主按钮统一使用深蓝实色底、白色文字与轻阴影，不使用蓝粉渐变。
- Home 指示条绝对定位在内容上方，背景必须透明，不得额外占用一块带底色的布局区域。
- 消息扩展功能区只保留灰蓝色图标和文字，不使用独立卡片、图标底板或多色渐变。

### 消息内容与长按菜单

- 文字、表情、图片、视频、语音、转账、位置、链接、通话和系统消息必须分别使用专属内容组件，不得统一套用默认文字气泡。
- 消息支持长按和右键打开操作菜单；固定提供编辑、复制、收藏、多选、撤回、引用、转发与删除，其中不适用于角色消息或正文旧记录的操作显示为禁用。
- 多选模式必须有明确选中态与批量收藏、删除、完成操作；引用和编辑状态显示在输入栏上方并允许取消。
- 消息多选圆钮固定为 1:1 正圆：未选中为白底中性灰边，选中为电波蓝底；对号必须小于圆钮直径的一半。消息行选中背景固定使用
  `#F2F1F3`，不得跟随 Char/User 改成蓝底或粉底。
- 发送任意消息前立即收起扩展面板、消息操作菜单和媒体输入弹层，不等待 API 返回，避免遮挡聊天页面。

## 5. Char 信息与数据规则

- 单人角色卡创建默认 Char 时，头像优先来自酒馆 `getCharAvatarPath('current')`。
- 备注与头像入口位于私聊设置；首页不再放置 Char 编辑卡片。
- 用户备注作为手机全局显示名：非空备注优先于原始角色名，首页、列表、导航、头像标签、转发列表、状态档案、空间与钱包统一读取
  `displayIdentityName`。清空备注回退原名。原始角色名继续用于身份匹配与生成寻址，不覆写角色卡原始数据或历史正文。
- 自定义头像和备注使用 `角色卡 key :: Char key` 存入脚本变量；它们可跨同一卡片的聊天复用。
- 手机消息和 App 快照继续使用 `角色卡 key :: 聊天 key :: Char key` 隔离，资料覆盖不能改变聊天隔离边界。
- 多人卡或群聊只为正文中已解析出的实际 Char 建档；不得把容器卡名或群名当作某个 Char。

## 6. 评审清单

- 搜索业务 `.vue` 文件，不得发现 h1–h6、可见原生 select/radio/checkbox。

- API 配置及生成参数字段标题使用 strong，与其他设置主标题同级；控件和操作按钮采用可读字号，说明文字保留次级层次。
- 音乐首页双列等高封面卡：歌名最多两行、歌手一行、感想三行，完整歌名和感想通过独立“查看感想”入口展开。
- 角色音乐封面绑定自动搜索解析出的 radioTrack，不随其他手动选歌改变；封面加载失败回退渐变，封面成功时用暗色遮罩保证文字对比度。
