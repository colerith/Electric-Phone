# 电波手机目录

- `index.ts`：脚本入口与样式注册。
- `app.vue`：手机外壳、路由和应用间协调。
- `schemas.ts`：持久化数据结构与版本号。
- `components/space`：空间五栏、动态、个人主页、每日匿名树洞。
- `components/chat`、`music`、`wallet`：对应应用界面。
- `components/settings`、`shared`、`shell`、`apps`：设置、公共控件、外壳及其他应用。
- `services/core`：身份、存储、备份、网络和系统服务。
- `services/generation`：生成调度、协议、提示上下文和翻译。
- `services/chat`、`space`、`music`、`wallet`、`apps`：按功能划分的数据与业务逻辑。
- `stores`：跨组件共享状态。
- `styles/base`、`apps`、`settings`：基础、应用、设置样式。
- `assets/badges`：随包发布的 Noto Emoji / Fluent Emoji 彩色徽章、来源说明与对应 Apache 2.0 / MIT 许可；`services/space/profile-badges.ts`
  定义分类和资料字段校验。
- `assets`：图片及图标；`prompts`：提示词；`tests`：回归测试；`docs`：项目文档。

## 数据归属

同一角色卡下，账户、币种、银行信息、余额、流水、账户选择和各角色的空间/钱包封面保存在全局角色存储中，切换 chat 继续使用。其他角色卡隔离。动态、评论、聊天与每日树洞内容仍按 chat 保存。

每个旧 chat 的钱包只迁移一次；流水源使用 chat 前缀，重放当前 chat 只替换自己的楼层来源。第一次迁入的余额为共享账本起点，后续旧 chat 合入其独有流水，已有共享余额设置优先。删除流水的记录一同保存，防止旧 chat 恢复已删除的数据。备份包含角色共享存储。

空间使用统一动态视图，兼容旧 zone 内容与互动；消息应用保留消息、联系人和个人资料/钱包入口。树洞内容由用户匿名发布或手动请求 AI 生成，不接入真实公共社交网络。

匿名头像使用 [DiceBear Bottts Neutral](https://www.dicebear.com/styles/bottts-neutral/)，原作者 Pablo Stanley。头像请求使用不可读种子，不传递账号或私聊文本；头像网络失败时使用本地回退图标。

消息反应保存在对应 `PhoneMessage.reactions`，只接受内置 Emoji 库中的表情；`services/chat/message-reactions.ts` 负责校验与切换，`components/chat/WaveReactionPicker.vue` 提供快捷栏与分类选择。最近使用保存在脚本设置中。

角色消息反应写入用户消息的 `characterReactions`，保存成员 charKey 与 Emoji。模型顶层可选 `reactions:[{message_id,emoji,actor_key?}]`（每轮最多一个），只有当前线程未撤回、已发送的用户消息可作为目标；群聊 actor_key 必须属于当前群成员。


## 服务器持久化（1.1.70）

`services/core/durable-storage.ts` 统一设置、联系人和聊天的读写。沿用酒馆助手变量镜像，同时把全局配置写入 `SillyTavern.extensionSettings.wave_phone_durable_v1` 并触发 `saveSettingsDebounced`。通过同源 `/api/files/upload` 将全局资料和各聊天分别写到酒馆账号的 `user/files/wave-phone-v1-*-0.json` / `*-1.json`，成功后轮换，保留上一份。文件名根据完整角色/聊天作用域生成固定散列，文件内部校验原始作用域；恢复不依赖浏览器缓存或脚本 ID。没有自动过期或自动清理历史聊天文件。

启动挂载前读取全局存档，每次首次进入某个聊天时读取对应存档。带保存时间的本地新数据优先于旧服务器快照；读取失败不视为新空档，损坏快照尝试另一份，所有候选均失败则停止恢复和覆盖。连续编辑按约 350ms 合并保存，上传串行执行；失败保留队列，界面展示错误并支持重试。导入 ZIP 会等待服务器文件写入成功后才重新载入。

`storage-migration.ts` 只依据当前聊天已有的旧作用域执行迁移，不根据当前列表序号猜测全局联系人归属。角色卡文件名优先作为稳定标识；文件重命名和复制卡片并非同一标识。原有备份需原角色名与原聊天文件名同时匹配，才允许将旧序号迁到新标识。旧键保留，跨角色/聊天不自动覆盖。

服务器存档属于当前酒馆账号，服务器目录被删除或两份存档都不可用时，仍需手动 ZIP 备份。此机制不承诺恢复升级前已彻底丢失的数据，也不提供多设备并发编辑合并。关闭页面前可在备份页使用“立即保存到服务器”并确认已保存。

实现参考：[柏宝绘设置存储](https://github.com/baibai-git/ST-BaiBai-Image/blob/main/src/state/settings.ts)、[服务器文件接口封装](https://github.com/baibai-git/ST-BaiBai-Image/blob/main/src/floor/upload.ts)。
